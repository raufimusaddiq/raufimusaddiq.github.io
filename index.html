03 How I work

Software should explain itself.

I like systems with explicit boundaries: clear ownership of state, observable failure modes, and architecture that can survive the next feature without becoming mysterious.

01

Correctness before cleverness

Use AI where interpretation helps. Keep critical state transitions deterministic, testable, and auditable.

02

Durability is a feature

Retries, idempotency, recovery, and explicit ownership are product behavior, not implementation trivia.

03

Operate what you build

Deployment, observability, failure recovery, and security boundaries belong in the design from the start.
